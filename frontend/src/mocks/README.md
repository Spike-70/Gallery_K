# `src/mocks` — 데모 전용 계층

백엔드 없이 전 화면을 시연하기 위한 임시 계층입니다. **제품 코드가 이 폴더를 알지 못하도록**
설계되어 있으며, 아래 3단계로 흔적 없이 제거됩니다.

## 구조

| 파일 | 역할 |
|---|---|
| `lib/mockClient.ts` | 지연·오류를 흉내 내는 유틸(`mockDelay`, `mockFail`) |
| `lib/imageFactory.ts` | 외부 요청 없이 그림 이미지를 만드는 SVG data URI 생성기 |
| `lib/demoStorage.ts` | 세션·열람 기록만 브라우저에 남긴다. 키는 전부 `gk.demo.` 로 시작한다 |
| `db.ts` | 데모 세션 동안 살아 있는 **가변 인메모리 상태**(로그인·설정·편집·차단이 실제로 반영된다) |
| `data/*.ts` | 초기 시드 데이터. 모두 API 명세서 §3의 **서버 원형(snake_case) 타입**을 그대로 따른다 |
| `handlers/*.ts` | 엔드포인트 1:1 대응 함수. 실제 API와 **동일한 응답 스키마**를 반환한다 |

## 데모 제거 절차

1. **스위치 끄기** — `.env`의 `VITE_USE_MOCK=false`. 이 시점에 모든 목 경로가 차단된다.
2. **호출 교체** — 각 `entities/*/api/*.ts`에서 `// [API]` 주석 블록을 해제하고
   그 아래 `// [MOCK]` 블록을 지운다. 두 블록은 항상 붙어 있으며 반환 타입이 동일하다.
   ```bash
   grep -rn "\[MOCK\]" src/   # 교체할 지점 전수
   ```
3. **폴더 삭제** — `rm -rf src/mocks` 후 `src/shared/config/env.ts`의 `useMock` 필드와
   `.env`의 `VITE_USE_MOCK`을 지운다.

`src/mocks`를 지웠을 때 컴파일 오류가 나는 곳이 곧 2단계에서 빠뜨린 지점이다.

이미 데모를 열어 본 브라우저에는 `gk.demo.*` 키가 남는다. 제품 코드는 이 키를 읽지
않으므로 지우지 않아도 동작에 영향이 없지만, 깨끗이 치우려면 콘솔에서 한 줄이면 된다.

```js
Object.keys(localStorage).filter((k) => k.startsWith('gk.demo.')).forEach((k) => localStorage.removeItem(k))
```

## 규칙

- 목 핸들러는 **도메인 타입이 아니라 서버 원형 타입**을 반환한다. 변환은 실제 API와
  동일하게 `entities/*/api/`의 매퍼가 담당한다. 그래야 매퍼가 데모에서도 검증된다.
- 목이 화면 로직을 대신하지 않는다. 발행 조건 판정 같은 도메인 규칙은 서버 몫이므로
  `db.ts`가 서버를 흉내 내어 계산한다(화면 코드에 규칙이 새어 들어가지 않게 한다).
- **브라우저에 남기는 것은 세션과 열람 기록뿐이다.** 새로고침에 로그인이 풀리면
  90일 자동 로그인(PRD GAP-14)을 보여주려는 화면이 정반대로 동작하기 때문이다.
  전시 원고·업로드한 이미지는 일부러 남기지 않는다 — 거기까지 흉내 내면 목이 사실상
  백엔드가 되고, 실제 API로 바꿀 때 지워야 할 코드가 늘어난다.
- 보존은 `db` 객체의 접근자와 `PersistentSet`이 처리한다. **핸들러에는 저장 코드가
  한 줄도 없다** — 평소처럼 `db.currentUserId = ...` 로 쓰면 된다.
