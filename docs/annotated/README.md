# 갤러리 K 설계 문서 — 초보자용 해설판

이 폴더의 문서는 `docs/` 폴더에 있는 **설계 문서 원문에 설명을 덧붙인 것**입니다.

원문은 개발자끼리 오해 없이 일하기 위해 쓴 글이라, IT 지식이 없으면 읽기 어렵습니다. 그래서 원문은 **한 글자도 바꾸지 않고 그대로 두고**, 중간중간에 이런 상자를 끼워 넣었습니다.

> **📘 쉬운 설명**
>
> 바로 위(또는 아래) 내용이 무슨 말인지, 왜 그렇게 정했는지를 일상어로 풀어 씁니다.

---

## 이 문서들은 무엇인가요?

**갤러리 K**는 "매일 아침 큐레이터가 고른 그림 12점을 보여주는, 초대받은 사람만 들어올 수 있는 작은 온라인 미술관"입니다. 이걸 실제로 만들려면, 만들기 전에 **무엇을 어떻게 만들지 글로 정해두어야** 합니다. 그 글이 설계 문서입니다.

집을 짓는 것에 비유하면 이렇습니다.

| 문서 | 집짓기로 치면 | 없으면 생기는 일 |
|---|---|---|
| **PRD** (기획서) | "방 3개짜리 집을 짓자"는 결정 | 무엇을 만들지 모른다 |
| **데이터베이스 설계서** | 창고에 무엇을 어떤 칸에 넣을지 정한 도면 | 정보가 여기저기 흩어져 나중에 못 찾는다 |
| **API 명세서** | 방과 방 사이의 문·복도 규격 | 앞부분과 뒷부분이 서로 말이 안 통한다 |
| **디자인 시스템** | 벽 색깔·손잡이 높이·창문 크기 규격집 | 방마다 손잡이 높이가 달라진다 |
| **백엔드 아키텍처** | 보이지 않는 배관·전기 배선 도면 | 물이 새고 어디서 새는지 못 찾는다 |
| **프런트엔드 아키텍처** | 눈에 보이는 방·가구 배치 도면 | 화면 코드가 뒤엉켜 고칠 수 없게 된다 |
| **UX 설계서** | "현관에 들어오면 어디로 가게 되는가"라는 동선 계획 | 사용자가 길을 잃는다 |

## 읽을 때 알아두면 좋은 것

**표가 많은 이유** — 설계 문서는 "읽는 글"이 아니라 "찾아보는 글"입니다. 개발자는 이 문서를 처음부터 끝까지 읽지 않고, 지금 만들고 있는 부분만 찾아봅니다. 그래서 줄글보다 표가 많습니다.

**`이렇게 생긴 글씨`** — 회색 배경의 글씨는 **컴퓨터가 알아듣는 이름**입니다. 사람이 읽는 말이 아니라 코드에 그대로 적히는 글자라서, 띄어쓰기 하나만 달라도 다른 것이 됩니다.

**§ 기호** — "몇 번째 절"이라는 뜻입니다. `§4.3`은 "4장 3절"입니다. 문서끼리 서로를 가리킬 때 씁니다.

**결정에 이유가 붙어 있는 이유** — 설계 문서에서 가장 중요한 건 "무엇을 정했나"가 아니라 **"왜 그렇게 정했나"**입니다. 1년 뒤에 누군가 "이거 왜 이렇게 되어 있지?" 하고 물을 때, 이유가 적혀 있지 않으면 함부로 바꾸거나, 반대로 바꿔도 되는 걸 무서워서 못 바꿉니다.
