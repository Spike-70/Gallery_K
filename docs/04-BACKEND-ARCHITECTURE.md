## 1. 원칙

| # | 원칙 |
|---|---|
| BA-1 | 계층은 단방향이다: `api → service → db`. 역방향·건너뛰기를 정적 검사로 막는다 |
| BA-2 | 라우트는 얇다. 입력 바인딩 → 서비스 호출 → 응답 조립 외의 분기를 두지 않는다 |

| BA-7 | 부수효과는 이력 행을 남긴다 |

## 2. 시스템 구성

| 구성 요소 | 역할 |
|---|---|
| CloudFront | 단일 진입점. `/` → S3(프런트 정적), `/api/*` → API Gateway. 동일 오리진이므로 CORS·SameSite 문제가 없다 |
| S3 `web` | 프런트 빌드 산출물 |
| S3 `media` | 이미지. **비공개.** 접근은 presigned URL로만 |
| Lambda `api` | Chalice 앱 본체. 모든 HTTP 요청과 이미지 처리를 담당한다 |
| Lambda `scheduler` | Chalice 스케줄 핸들러 1개. 알림 발송 + 야간 정리 |
| RDS PostgreSQL | 주 데이터 저장소 |
| CloudWatch Logs | 구조화 로그·경보 |

**MVP에서 쓰지 않는 것** — SQS·SNS·Redis·이벤트 워커 Lambda·S3 이벤트 트리거·RDS Proxy·VPC 배치와 NAT·Provisioned Concurrency·분산 추적. 회원 100명 규모에서 이들은 비용과 실패 지점만 늘린다. 필요해지는 시점(§15)을 정해 두고 그때 도입한다.

**Lambda가 둘인 이유** — 사용자별 알림 시각 예약 발송은 요청과 무관한 주기 실행이 있어야만 성립한다. 그 외 비동기 처리는 두지 않으며, 이미지 리사이즈는 요청 안에서 동기로 끝낸다.

**네트워크** — Lambda는 VPC 밖에 둔다. RDS는 보안 그룹으로 접근원을 제한하고 SSL을 강제한다. VPC 배치는 NAT 비용과 콜드 스타트를 늘리므로 이 규모에서는 채택하지 않는다.

## 3. 디렉터리 구조

```
backend/
├── app.py                  # Chalice 진입점. 블루프린트 등록 + 스케줄 핸들러 선언
├── migrations/             # Alembic. 배포 패키지 제외
└── chalicelib/
    ├── config/             # settings(단일 설정 객체) · constants
    ├── core/               # envelope · errors · context · middleware · decorators
    │                       # security · pagination · logging · timeutil
    ├── db/
    │   ├── engine.py       # 엔진·세션
    │   ├── query.py        # 공용 DB 헬퍼 (§4)
    │   ├── queries/        # 헬퍼로 표현되지 않는 명명된 전용 질의
    │   └── models/         # 테이블 정의 + 열거형
    ├── schemas/            # 요청·응답 DTO
    ├── services/           # 도메인 규칙
    ├── integrations/       # 외부 어댑터. boto3·외부 HTTP는 여기서만 import
    ├── api/
    │   ├── deps.py
    │   └── routes/         # 경로별 블루프린트 (public·auth·exhibitions·artworks·me·admin/*·system)
    ├── jobs/               # 스케줄 핸들러가 호출하는 루틴
    └── utils/              # 도메인 무지식 순수 함수
```

**배치 기준** — 테이블이면 `db/models`, 도메인 규칙이면 `services`, HTTP 모양을 알면 `schemas`/`api`, 외부 호출이면 `integrations`, 모든 요청이 거치면 `core`. 어디에 둘지 애매한 모듈은 책임이 두 개다. 나누고 다시 판단한다.

## 4. DB 접근 계층

**테이블별 리포지토리를 두지 않는다.** 대신 관계 탐색·필터·정렬·페이지네이션을 내재한 **범용 고수준 헬퍼 하나**(`db/query.py`)를 두고 서비스가 직접 호출한다. 테이블 수만큼 CRUD 래퍼를 복제하는 구조를 만들지 않는 것이 목적이다.

### 4.1 헬퍼가 제공하는 연산

`fetch` · `fetch_one` · `exists` · `count` · `aggregate` · `insert` · `bulk_insert` · `update` · `bulk_update` · `upsert` · `delete`.

### 4.2 표현 수단

| 수단 | 내용 |
|---|---|
| 필터 | `필드__연산자=값` 형식의 조회 표현. 비교·포함·범위·부분일치·NULL 판정을 지원하고 AND/OR/NOT 결합이 가능하다 |
| 관계 탐색 | 필터·정렬 키에 `관계__필드` 경로를 쓰면 필요한 조인이 자동 구성된다 |
| 관계 로딩 | 조인 즉시 로딩 / 별도 질의 일괄 로딩을 선택한다. **기본은 지연 로딩 금지** — N+1의 출처를 원천 차단한다 |
| 정렬·제한 | 다중 정렬 키(내림차순 접두), 개수 제한, 오프셋·커서 페이지네이션 |
| 투영 | 반환 컬럼 선택, 모델 인스턴스 / 사전 형태 선택 |
| 집계 | 그룹 기준과 집계 함수를 인자로 받는다 |
| 잠금 | 행 잠금 옵션 |

### 4.3 규칙

- 서비스는 이 헬퍼와 명명된 전용 질의만 사용한다. **문자열 SQL 조립을 금지**하며 파라미터 바인딩만 쓴다.
- 헬퍼로 표현되지 않는 질의(측면 조인, 배타 제약 활용, 복합 집계)는 `db/queries/`에 **이름 있는 함수**로 격리한다. 서비스에 SQL이 흩어지지 않게 하는 것이 이 폴더의 유일한 존재 이유다.
- 삭제는 DB의 `ON DELETE`에 위임한다(DB 문서 §3.1). 애플리케이션이 자식 행을 루프로 지우지 않는다.
- **모델 객체는 서비스 밖으로 나가지 않는다.** 서비스는 응답 DTO를 반환한다. 자격증명 필드의 우발적 직렬화와 세션 종료 후 지연 로딩 사고를 구조적으로 막는다.

### 4.4 연결 관리

엔진은 모듈 로드 시 1회 생성한다. 풀은 `NullPool`, `pool_pre_ping` 활성, 연결·질의 타임아웃은 Lambda 타임아웃보다 짧게 둔다. 요청당 세션 1개·트랜잭션 1개가 기본이며 **커밋은 미들웨어의 책임**이다 — 서비스는 세션을 받되 스스로 커밋하지 않는다. 외부 호출(S3·웹푸시)은 트랜잭션 안에서 하지 않는다.

## 5. 계층 규칙

```
app.py → api/routes → services → db(query · models)
                    ↘ schemas          ↘ queries
         services → integrations
         core: 전 계층에서 참조 가능
```

| 규칙 |
|---|
| `services`는 `chalice`·`api`·`schemas`를 import 하지 않는다 |
| `api`는 `db.models`를 직접 import 하지 않는다 |
| `db`·`integrations`는 상위 계층을 import 하지 않는다 |
| `core`는 어떤 상위 계층도 import 하지 않는다 |

`import-linter` 계약으로 CI에서 강제한다. **아키텍처 규칙은 테스트로 존재해야 유지된다.**

## 6. 요청 파이프라인

미들웨어를 바깥에서 안쪽 순으로 조립한다.

| # | 미들웨어 | 책임 |
|---|---|---|
| 1 | `request_context` | 요청 ID 발급, 시작 시각·KST 오늘 계산 |
| 2 | `access_log` | 시작·종료 구조화 로그 |
| 3 | `error_boundary` | 모든 예외를 표준 봉투로 변환 |
| 4 | `maintenance_gate` | 점검 모드 시 공개·시스템 경로 외 차단 |
| 5 | `csrf_guard` | 변경 메서드의 커스텀 헤더 확인 |
| 6 | `db_session` | 요청 스코프 세션을 **지연 생성**으로 등록. 정상 종료 시 커밋, 예외 시 롤백 |
| 7 | `authentication` | 세션 쿠키 검증·무효화 카운터 대조·슬라이딩 갱신 |
| 8 | `response_finalize` | 봉투 `meta` 채우기, 캐시 헤더·쿠키 부착 |

**순서의 근거** — 오류 경계가 인증보다 바깥이어야 인증 실패도 봉투로 나간다. 인증이 DB를 읽으므로 세션이 그보다 바깥에 있어야 하며, 세션 없이 끝나는 요청이 커넥션을 점유하지 않도록 지연 생성한다.

## 7. 데코레이터

라우트별 관심사는 전부 데코레이터로 흡수한다. **라우트 본문에 권한·검증·기록 코드를 쓰지 않는다.**

| 데코레이터 | 역할 |
|---|---|
| `@require(등급)` | `PUBLIC` \| `MEMBER` \| `CURATOR` 권한 강제. 선언부에서 권한이 눈으로 보인다 |
| `@owns(자원)` | 대상 자원이 요청자 소유인지 검증(본인 구독 해제 등). 등급으로 표현되지 않는 소유권 판정을 라우트에서 반복하지 않는다 |
| `@body(스키마)` / `@query(스키마)` | 입력 파싱·검증. 실패 시 필드 오류를 자동 생성 |
| `@paginated(모드)` | 페이지네이션 파라미터 처리 |
| `@etag(원천)` | 조건부 요청 처리 |
| `@throttled(범위)` | 시도 제한 |
| `@audited(액션)` | 성공 시 감사 로그 자동 기록 |

데코레이터는 **선언적 메타데이터**이기도 하다. 테스트가 전 라우트를 순회해 권한 데코레이터 누락을 검출한다(§12).

## 8. 횡단 관심사

### 8.1 설정

`config/settings.py`가 **모든 환경변수를 읽는 유일한 지점**이다. `python-dotenv`로 `.env`를 로드한 뒤 검증된 단일 설정 객체를 만들어 노출하며, 사용처는 이 객체만 참조한다. **다른 모듈에서 `os.environ` 직접 접근을 린트로 금지한다.**

| 계층 | 출처 |
|---|---|
| 로컬 개발 | `backend/.env` (커밋 금지. `.env.example`을 템플릿으로 둔다) |
| 배포 | Chalice 스테이지 환경변수 |

`.env`가 없어도 배포 환경에서 동작해야 하며, 필수 값이 비어 있으면 **기동 시점에 실패**한다(요청 처리 중에 발견되지 않게 한다). 별도 시크릿 저장소는 두지 않는다 — 값의 종류를 이원화하면 "어디를 봐야 하는가"가 매번 문제가 된다.

**환경변수는 배포로만 바뀌는 값**이고, 운영 중 조정되는 값은 `app_setting` 테이블이다(DB 문서 §4.9). 이 구분을 흐리지 않는다.

### 8.2 오류

`AppError`를 기반으로 검증·인증·권한·부재·충돌·크기초과·제한·의존성·내부 오류로 분기한다. 각 예외는 코드·문구·상세·재시도 가능 여부를 갖고, **오류 코드 카탈로그는 레지스트리 하나**로 표현한다. 카탈로그에 없는 코드로 예외를 발생시키는 것을 테스트가 금지한다.

원천 예외 변환은 한 곳에 모은다: 스키마 검증 오류 → 필드 오류, **제약 위반 → 제약명 기반 코드 매핑**(사전 조회로도 경쟁 조건은 남으므로 필수), 버전 충돌 → 충돌 코드, 연결 오류 → 의존성 오류, 그 외 → 내부 오류(상세는 로그에만).

### 8.3 로깅

JSON 한 줄. 필수 필드는 시각·수준·요청 ID·경로·메서드·상태·소요시간·행위자·이벤트. 전화번호는 마스킹하고 비밀번호·해시·토큰·요청 바디 전체·바이너리는 기록하지 않는다. **마스킹은 로거 필터가 자동 수행한다** — 호출부의 주의에 의존하지 않는다.

### 8.4 시간

시간을 만드는 모듈은 하나뿐이다(현재 UTC/KST, KST 오늘, 표시 라벨). 다른 파일에서 현재 시각을 직접 얻는 것을 린트로 금지한다. 테스트는 이 모듈을 고정해 날짜 경계를 검증한다.

### 8.5 설정 캐시

`app_setting`은 거의 변하지 않고 거의 모든 요청이 읽는다. 프로세스 전역에 짧은 TTL 캐시를 둔다. 인스턴스가 여러 개이므로 TTL만큼 전파 지연이 있으며, 이는 모든 설정 항목에서 허용 가능하다.

## 9. 도메인 서비스

각 서비스의 **책임과 불변식**만 정한다. 메서드 구성은 구현 시 결정한다.

| 서비스 | 책임 |
|---|---|
| `exhibition_service` | 현재 전시 조회, 연장 판정과 라벨, **발행 규칙 적용**, 발행 되돌림 금지, 숨김·해제, 백필 차단 |
| `exhibition_admin_service` | 달력, 드래프트, 이어쓰기, 편집 모드 결정 |
| `artwork_service` | 슬롯 CRUD, 순서 변경, 완성도 및 카운터 갱신 |
| `auth_service` · `session_service` | 가입·로그인·세션·비밀번호·시도 제한 |
| `view_log_service` | 입장·열람 기록(UPSERT, 실패해도 사용자에게 노출하지 않는다) |
| `member_service` | 회원 목록·대행 가입·차단·초기화 |
| `notice_service` · `setting_service` | 공지, 전역 설정 |
| `stats_service` · `archive_service` | 통계, 아카이브 목록 |
| `media_service` | presigned URL 발급 (§10) |
| `image_service` | 업로드 검증·리사이즈 파이프라인 |
| `notification_service` | 알림 큐 생성·발송·스킵 판정 |
| `audit_service` | 감사 기록 |

**발행 전환은 단 하나의 함수에서만 일어난다.** 제목 저장·그림 저장·삭제·순서 변경 등 모든 변경 경로가 마지막에 그 함수를 호출한다.

## 10. 미디어

S3 버킷은 비공개이며 **접근은 presigned URL로만** 이루어진다. CloudFront 서명 쿠키·키페어는 사용하지 않는다.

### 10.1 업로드 — presigned POST

| 단계 | 동작 |
|---|---|
| 1 | 클라이언트가 슬롯·파일명·형식·크기를 담아 업로드 자격 발급을 요청한다 |
| 2 | 서버가 슬롯 행을 확보하고 **presigned POST**(업로드 URL + 정책 필드 묶음)를 발급한다. 상태는 `uploading` |
| 3 | 클라이언트가 받은 필드를 그대로 담아 S3에 직접 POST 한다 |
| 4 | 클라이언트가 완료를 통지하면 서버가 **그 요청 안에서 동기로** 원본을 검증·변환하고 `ready`로 전환한다 |

**presigned POST를 쓰는 이유** — 정책에 크기 상한·콘텐츠 타입·키 접두를 **서버가 서명해 못박을 수 있다.** PUT 방식은 이 조건을 강제할 수단이 제한적이다. 20MB 파일이 API Gateway를 통과할 수 없다는 제약도 함께 해결된다.

**동기 처리를 쓰는 이유** — 이벤트 워커를 두면 S3 이벤트 구독·별도 Lambda·처리 지연 폴링·정체 감지 배치가 함께 따라온다. 한 장 처리 시간은 요청 타임아웃 안에 충분히 들어가고, 여러 장은 클라이언트가 병렬 업로드하므로 요청도 병렬로 나뉜다. 응답이 곧 완료 통지이므로 **클라이언트 폴링이 필요 없다.**

**처리 규격** — 썸네일·디스플레이·저해상도 플레이스홀더를 생성하고, EXIF 방향을 보정하고, EXIF 개인정보를 제거하고, 색 프로파일을 sRGB로 변환한다. 색 변환은 미술 작품에서 특히 중요하다.

**검증과 실패** — 서명 정책(1차)과 서버의 매직 바이트·픽셀 수 검사(2차)로 이중 확인한다. 실패는 상태와 사유 코드를 기록하고 **재업로드로만 복구**한다. 자동 재시도는 하지 않는다 — 대부분 파일 자체의 문제이고 재시도는 대기 시간만 늘린다.

### 10.2 다운로드 — presigned GET

이미지 URL은 응답을 만드는 시점에 **presigned GET URL**로 발급한다. 유효기간은 설정 값으로 둔다. 서명이 URL에 담기므로 응답 본문 캐싱은 하지 않으며, 이미지 자체는 브라우저·CDN 캐시가 받는다.

**오브젝트 키** — 업로드 착지 경로와 확정 경로를 분리한다. 처리에 실패한 업로드가 서비스 경로에 남지 않게 하기 위함이다.

## 11. 알림과 배치

스케줄 핸들러는 **하나**이며 두 가지 일을 한다.

| 루틴 | 주기 | 내용 |
|---|---|---|
| 알림 발송 | 짧은 주기 | 발송 예정 시각이 지난 대기 행을 배치 처리. 4xx 응답이면 구독 비활성화, 5xx면 재시도 누적 후 실패 처리. 컷오프 초과분은 발송하지 않고 스킵 기록 |
| 야간 정리 | 하루 1회 | 보존기간 초과 행 삭제, 비활성 구독 정리, 미참조 S3 오브젝트 회수, 연장 지속 시 큐레이터 알림 |

큐 생성은 발행 트랜잭션 안에서 이루어진다. **중복 기동은 `dedupe_key` 유니크와 조건부 상태 갱신으로 무해하다.** 모든 루틴은 멱등하며 처리 0건도 로그를 남긴다 — 잡이 죽었는지 알 수 있어야 한다.

알림 문구는 전시 제목까지만 담고 클릭 시 첫 화면으로 보낸다. 같은 날 배너가 쌓이지 않도록 태그를 지정한다.

## 12. 테스트

| 종류 | 대상 |
|---|---|
| 단위 | 도메인 규칙 — 연장 판정, 발행 조건, 편집 모드, 알림 스킵 |
| 통합 | DB 헬퍼·전용 질의·제약 위반·마이그레이션 (실제 PostgreSQL) |
| 계약 | 라우트 입출력, 봉투 구조, 오류 코드, 권한 |

**반드시 있어야 하는 것** — 연장 시나리오 전체 · 발행 후 조건이 깨져도 발행 상태 유지 · 백필 거부와 과거 발행본 수정 허용 · 이어쓰기 원자성 · 날짜 경계의 입장 기록 · 연장일 알림 미발송과 컷오프 스킵 · 로그인 실패 차단 · 미가입·차단·오답의 동일 응답 · 숨김 시 직전 전시 노출 · 탈퇴 시 익명화.

**규약 준수 메타 테스트** — ① 전 라우트에 권한 데코레이터가 있다 ② 전 응답이 봉투 스키마를 만족한다 ③ 발생하는 오류 코드가 카탈로그에 있다. 개별 기능 테스트가 아니라 새 라우트가 자동으로 검사 대상이 되게 하는 장치다.

## 13. 보안

| 영역 | 조치 |
|---|---|
| 인증 | 서명 토큰을 HttpOnly·Secure·SameSite 쿠키로만 전달한다. 응답 바디에 넣지 않는다 |
| 세션 무효화 | 무효화 카운터 대조 |
| 비밀번호 | bcrypt. 실패 경로도 동일 시간이 걸리게 한다 |
| 권한 | 서버에서만 판정한다(`@require`·`@owns`) |
| 입력 | 스키마 + DB 제약 이중 |
| SQL | ORM·바인딩 파라미터만. 문자열 조립 금지 |
| 업로드 | 서명 정책 조건 + 서버측 실제 형식 재검증 |
| 이미지 접근 | 비공개 버킷 + presigned URL |
| 검색 노출 | 전 응답에 색인 거부 헤더 |
| 보안 헤더 | HSTS·콘텐츠 타입 스니핑 차단·리퍼러 정책·권한 정책 |
| 로그 | 민감 필드 자동 마스킹 |
| 감사 | 관리자 변경 조작 전건 기록 |
| 의존성 | CI에서 취약점 점검 |

**존재를 숨기는 규칙** — 미가입·차단·오답 로그인은 모두 같은 응답을 준다. 미가입 번호의 재설정 요청은 성공 응답을 주되 발송하지 않는다. 미발행·숨김 전시는 부재로 응답한다. 다만 회원의 관리자 API 접근은 숨기지 않고 권한 없음으로 응답한다.

## 14. 배포

| 스테이지 | 용도 |
|---|---|
| `dev` | 로컬. 도커 PostgreSQL + `.env` |
| `prod` | 운영 |

**파이프라인** — 검증(린트·타입·아키텍처 계약·테스트) → **마이그레이션 독립 실행**(실패 시 배포 중단) → 배포 → 스모크(헬스·첫 화면·로그인 왕복) → 실패 시 직전 버전 롤백.

배포 금지 시간대는 아침 관람 피크다. 인프라는 MVP 동안 최소 수동 구성으로 두고, 자원이 늘어나는 시점에 코드형 인프라를 도입한다.

**콜드 스타트** — 패키지를 작게 유지하고, 엔진·설정을 모듈 로드 시 준비하고, 외부 어댑터는 사용 시점에 import 한다. ARM64 휠 문제를 피하기 위해 psycopg3을 쓴다.

## 15. 관측성과 확장 시점

로그는 CloudWatch에 JSON으로 남기고 경보는 **적게** 유지한다: 5xx 비율, 지연 p95, 알림 실패, DB 연결 오류, 배치 미실행. 운영자가 1인이므로 알림 피로가 곧 무시로 이어진다.

지금 도입하지 않은 것들의 **도입 조건**을 미리 정해 둔다.

| 대상 | 도입 시점 |
|---|---|
| RDS Proxy | 동시 실행이 늘어 연결 수가 인스턴스 상한에 근접할 때 |
| 이미지 처리 분리(워커) | 한 장 처리 시간이 요청 타임아웃을 위협할 때 |
| 큐(SQS) | 재시도·순서 보장이 실제로 필요한 부수효과가 생길 때 |
| 캐시 저장소 | 프로세스 캐시로 감당되지 않는 공유 상태가 생길 때 |
| VPC 배치 | 사설망 전용 자원에 접근해야 할 때 |
| 코드형 인프라 | 자원이 손으로 관리 가능한 수를 넘을 때 |
